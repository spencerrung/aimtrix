# Multiple accounts and local isolation

Aimtrix keeps one Matrix client active at a time. Settings → Accounts can switch to another saved account, add an account, or forget a dormant account. The sign-in and recovery screens also offer saved-account switching. An account is identified by its homeserver URL and Matrix user ID; the same user ID on a different homeserver is a separate account.

The browser stores a versioned credential vault under the existing session key, migrating the previous single-session record when another account is added. Native wrappers use their existing secure credential store for the same vault. The vault holds at most 16 accounts and rejects an additional account before changing the saved record. Each account retains its SDK sync and crypto databases, private search index, durable composer drafts, appearance/notification preferences, and last room. Switching stops the foreground client, active call and push subscription before starting the selected account. Only the foreground account registers this device for push. Account-bound notification routes ask before opening under another account.

Forgetting a dormant account removes its local credential first, then deletes that account's local sync/crypto databases, private search index, saved drafts, preferences and last-room state. A failed local cleanup is reported in Settings so the user can clear site data. Forgetting does not log out a remote device, revoke a token, remove other devices, or alter rooms on the server. Use server/device settings or sign out while the account is active for remote logout.

The browser account-switch checks use disposable identities. Unit/controller tests cover vault migration, lifecycle teardown and isolation, recovery switching, preferences and account routes. The disposable Synapse journey signs in two accounts in one browser, switches after an encrypted message, then checks that the first account's room, decrypted marker and draft are absent from the second account and restored on switching back. Until that CI journey passes, this is an implemented path with pending live interoperability evidence. Native secure-storage upgrade and physical notification delivery remain under [#175](https://github.com/spencerrung/aimtrix/issues/175) and [#176](https://github.com/spencerrung/aimtrix/issues/176).
