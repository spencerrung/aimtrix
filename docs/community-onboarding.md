# Community arrival and room administration

Aimtrix uses Matrix room topics as the short purpose shown to members. Moderators can write a welcome message and pin it through the existing room controls. In a Matrix space, **Manage space** lets a moderator add a joined room or subspace and mark direct children as recommended. Recommended rooms appear first in the space's arrival view. This is ordinary `m.space.child` state, so other Matrix clients can read the same relationship; no Aimtrix-only welcome event is required.

Room **Manage** provides join rules (invite, public, or knock where the room version supports it), history visibility, guest access, local aliases, public directory visibility, server ACL, and an upgrade to the homeserver's stable default room version when the member can send a tombstone. Changes that broaden access, remove an alias, alter ACL, or upgrade a room require confirmation. The client reads room state after an access write and reloads administration state after other writes. Alias creation checks resolution; directory and ACL changes check server readback. A replacement-room link is offered after upgrade. The public directory and space previews identify knock rooms as requests and invite-only previews as requiring an invitation. The UI does not offer restricted join rules because it has no validated allow-list editor; a room already using one displays its current value without pretending Aimtrix can edit it.

Space management writes both `m.space.child` and, for subspaces, `m.space.parent`. The member needs permission for both events. If a second write fails, Aimtrix attempts to restore the first and reports whether that rollback failed. Canonical-parent changes similarly attempt restoration after partial failure. The control edits only joined rooms or spaces and prevents direct and known descendant cycles. Removal changes the relationship, not the room or its history. Because Matrix graph events are independent writes, a concurrent moderator can still change them during an operation; refresh the space after a conflict.

Local validation: `npm run check` passed lint, 997 Vitest tests, TypeScript, production build, and bundle budgets; `npm run test:e2e` passed 138 Chromium tests with 8 intentional skips across desktop and mobile. Mocked SDK tests cover permission/readback flows and component confirmation. Desktop and phone screenshots of the join dialog were inspected. The advanced administration panels were component-tested but not browser-tested against a live room. Live validation still needs several real Matrix accounts with different power levels to test room joins, permission changes, graph writes, and upgrade navigation. No live homeserver or production room was changed by this implementation pass.
