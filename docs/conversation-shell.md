# Conversation shell

Polish 08 implements the [accepted interaction rules](design/interaction-rules.md) in the application. Threads, loaded-message search, and the Buddy Card / Room Lounge share one contextual surface. Opening one replaces the visible surface; closing it returns to the conversation without reopening another drawer. Main and thread text drafts, the current thread, drawer tab, search query, and detached reading position survive these switches within the mounted workspace.

At 1200px and wider, the contextual surface docks beside the conversation. Stored room-list and contextual widths are bounded together to leave at least 420px for the conversation. The existing keyboard/pointer resizing, collapse/restore choices, themes, accents, message density, bubbles, and original backdrops remain available. Contextual width is shared across drawers rather than maintaining competing thread/detail widths.

At 768–1199px, context replaces the conversation beside the room list. Below 768px, list, conversation, and context are separate surfaces. Hidden conversation controls leave the accessibility tree and focus order, and hidden timelines neither update their reading anchors from zero-sized geometry nor mark incoming messages read. Below 1200px in a viewport no taller than 480px, the rail yields space to the active conversation; Back and composition remain available. Visual viewport height and safe-area insets continue to size the shell.

Visible Back and browser Back/Forward use the same history chain. Switching contextual surfaces replaces the current context entry; resizing adds no entries. The browser history state holds opaque workspace-lifetime pointers, with room, space, and thread IDs kept in memory. Another workspace mount cannot restore the previous account's route data. Notification routing preserves unrelated history metadata and clears obsolete event parameters on room-only notifications. Reloading is still governed by the existing last-location preference and notification URL, not durable shell history.

Context entry focuses a heading rather than opening a software keyboard. Closing returns focus to the opener when available, otherwise the room heading. Temporary pickers handle Escape before the shell. Main composer secondary tools are available through the named More control. Thread More exposes the existing attachment upload path; broader thread composition parity and durable structured drafts remain [#153](https://github.com/spencerrung/aimtrix/issues/153). Member roles and removal actions now live in explicit member menus, preserving permissions, destructive confirmation, async feedback, and server operations.

Search clearly covers loaded messages only. Results occupy the contextual surface and explicitly open the chosen message in the conversation; searching no longer filters or reflows the main timeline. Homeserver-wide search and filters remain [#157](https://github.com/spencerrung/aimtrix/issues/157) and [#158](https://github.com/spencerrung/aimtrix/issues/158).

## Evidence and remaining boundaries

- Unit coverage exercises navigation history and workspace lifetime isolation, panel replacement and retained state, member actions, hidden-room read suppression, and stale async completion focus guards.
- Chromium coverage exercises desktop resizing, mobile/tablet Back and Forward with pixel reading anchors, resize without history changes, loaded search result navigation, and reduced-height main/thread controls. Shell screenshots are emitted with the Playwright results; Axe covers the contextual route alongside existing theme/accessibility scenarios.
- These browser checks emulate viewport and touch conditions. Physical iOS/Android software keyboards, native Back, WebView safe areas, screen readers, and Firefox/WebKit are separate acceptance evidence under [#162](https://github.com/spencerrung/aimtrix/issues/162) and [#175](https://github.com/spencerrung/aimtrix/issues/175).
- The shell adds no Matrix event type or plaintext fallback. Existing encrypted sending, attachments, history and session recovery retain their protocol paths. Old/unloaded thread roots, pagination and thread-read reconciliation remain separate work; a loaded demo thread is not proof of those boundaries.
