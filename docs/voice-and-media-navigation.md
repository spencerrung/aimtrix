# Voice messages and loaded-image navigation

The composer offers **Record a voice message** when the browser exposes microphone capture and `MediaRecorder`, and attachment sending is available. Microphone permission is requested only after **Start recording**, using the microphone selected in settings when one is configured. A recording stays local until the user previews it and selects **Send voice message**; **Discard** and closing the dialog stop the tracks and discard the bytes. Recording stops at five minutes or the configured upload-size limit. Device/permission failures leave a retryable state. Browsers without recording support can still attach audio files.

Sending uses the existing staged-attachment queue. It retains per-file progress, cancellation, retry, account-session cleanup, and encrypted-room upload handling. The event is a standard `m.room.message` with `msgtype: m.audio`, filename, MIME type and duration, so clients without voice-specific support receive an ordinary playable audio attachment. Aimtrix also writes the interoperable, currently unstable `org.matrix.msc3245.voice` marker and `org.matrix.msc1767.audio`, `org.matrix.msc1767.text`, and `org.matrix.msc1767.file` metadata used by Element. The codec/container is chosen from formats the browser reports as recordable; a generated waveform is included only if the browser can decode the result. Aimtrix-specific protocol events are not involved. The sender never falls back to plaintext in encrypted rooms.

An image viewer can move by Previous/Next buttons or Left/Right arrows through images **already loaded in the current room or thread timeline**. The viewer keeps authenticated/encrypted media retrieval, download, image fit, and the existing data-saver gate. It does not claim an account-wide or full-history gallery; older images become available through timeline pagination. Audio playback is explicit and follows the same data-saver gate as other media.

Unit tests cover voice event metadata, encrypted upload, snapshot recognition, queue isolation, and recorder review/permission behavior. The desktop/mobile Chromium fixture covers recording, preview, send, image navigation, download and accessibility. A separate browser check uses Chromium's real `MediaRecorder` with a generated audio stream, then decodes the captured WebM/Opus bytes and verifies non-silent samples; it does not simulate a physical microphone. The [disposable live harness](live-matrix-tests.md) exchanges a generated valid WebM/Opus tone in an encrypted Synapse room: a fake browser recorder, explicit send, ciphertext check, and exact decrypted download on a second Aimtrix account. The separate Element Web CI job opens the exact accepted encrypted event and checks its native player from Play to Pause and back to Play on completion. The [PR #228 live CI run](https://github.com/spencerrung/aimtrix/actions/runs/37126735069) passed that independent Element Web playback check. Local Docker is unavailable in this workspace. Physical microphone capture and playback, broader browser codec interoperability, and other independent Matrix clients remain open under [#168](https://github.com/spencerrung/aimtrix/issues/168).
