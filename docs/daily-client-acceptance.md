# Polished daily-client acceptance record

Status: browser release evidence in progress · October 1, 2026 (America/New_York) · owner [#164](https://github.com/spencerrung/aimtrix/issues/164)

This record joins the roadmap's nine daily-client journeys to reproducible checks. It is an evidence map, not a declaration that every Matrix client, native target, or provider has been accepted. The [capability baseline](capability-baseline.md) describes implementation; the [platform matrix](platform-acceptance.md) retains manual release targets. Synthetic demo content and disposable Matrix accounts are the only data used in these checks.

| Daily journey | Browser and live evidence | Remaining boundary |
| --- | --- | --- |

| Return after absence, catch up and reconcile reads | `e2e/attention.spec.ts`, `e2e/unread.spec.ts`; live `private-read-tracking-and-reminders`, `home-activity-and-follow-own-device-sync` | Long-running sync and real elapsed-day/account-scale behavior: [#163](https://github.com/spencerrung/aimtrix/issues/163) |
| Start a DM and compose across interruptions | `e2e/composition.spec.ts`, `e2e/aimtrix.spec.ts`; live `durable-room-thread-drafts-and-reattach`, `private-dm-backdrop-isolation` | Native storage lifecycle remains [#175](https://github.com/spencerrung/aimtrix/issues/175) |
| Upload encrypted media with cancellation and retry | `e2e/composition.spec.ts`, `e2e/voice-media.spec.ts`; live `authenticated-encrypted-media`, `encrypted-staged-attachments-and-retry` | Independent-client and physical-device media checks remain target-specific |

| Use the journeys with keyboard access and a narrow touch layout | `e2e/interactions.spec.ts`, `e2e/shell.spec.ts`, `e2e/browser-compat.spec.ts`, `e2e/first-use.spec.ts`; Chromium, Firefox and WebKit CI projects | Spoken screen-reader walkthrough and actual iOS/Android keyboards, safe areas and installed PWA remain [#162](https://github.com/spencerrung/aimtrix/issues/162)/[#175](https://github.com/spencerrung/aimtrix/issues/175) |

The Chromium suite runs desktop and Pixel 7 emulation against the built application in CI. Focused Firefox desktop and WebKit desktop/phone jobs cover the browser compatibility set. The all-theme active-conversation, thread and media screenshots are visual evidence for these layouts; Axe checks cover detectable WCAG A/AA issues, not speech output or physical touch behavior. The disposable Synapse/Dex harness and Element Web peer are described in [live Matrix evidence](live-matrix-tests.md), with private, allowlisted numeric diagnostics. An Element Web pass does not imply every listed journey was repeated in Element.

Current core blockers are [#160](https://github.com/spencerrung/aimtrix/issues/160), [#161](https://github.com/spencerrung/aimtrix/issues/161), [#162](https://github.com/spencerrung/aimtrix/issues/162), and [#163](https://github.com/spencerrung/aimtrix/issues/163). Keep #164 open while its dependency criteria remain unverified. Physical native installation, closed-app push, delegated OIDC, group calls and optional expansion issues retain their own gates; this browser acceptance record does not promote those targets.
