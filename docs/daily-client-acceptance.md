# Polished daily-client acceptance record

Status: RC6 hosted-PWA candidate deployed for field testing; device and provider acceptance open · October 5, 2026 (America/New_York) · owner [#164](https://github.com/spencerrung/aimtrix/issues/164)

This record joins the roadmap's nine daily-client journeys to reproducible checks. It is an evidence map, not a declaration that every Matrix client, native target, or provider has been accepted. The [capability baseline](capability-baseline.md) describes implementation; the [platform matrix](platform-acceptance.md) retains manual release targets. Synthetic demo content and disposable Matrix accounts are the only data used in these checks.

Public acceptance used fresh isolated Chromium contexts and synthetic demo content only. Local JSON results and screenshots were retained under `/tmp/aimtrix-implementation/deployed-qa/`, including `rc6-results.json`, `rc6-http.json` and `rollout/complete.json`.

The actual RC5-to-RC6 update check exposed an outstanding PWA delivery gap. Two old demo tabs retained their synthetic unsent drafts through rollout, but real `registration.update()` calls produced no waiting worker or update notice: RC5 and RC6 shipped identical worker/import bytes. A manual reload loaded the RC6 asset successfully. Old open tabs therefore need a manual reload; preserve any volatile draft before doing so. The follow-up in [PR #257](https://github.com/spencerrung/aimtrix/pull/257) adds build-specific worker identity and foreground discovery; its two-production-build browser regression passed, but that fix is not part of the immutable RC6 image. This rollout did **not** exercise a waiting-worker reload confirmation, automatic activation, or authenticated draft restoration, and the local worker-replacement test does not substitute for that deployed-origin evidence.
