# Polls and static locations

The composer offers poll creation and static-location sharing in joined Matrix rooms and threads. A poll has one question, 2–20 distinct answers, and an explicit choice about whether live results are disclosed. Poll roots, votes, and end events use the MSC3381 `org.matrix.msc3381.poll.*` event types with `m.reference` relations; incoming stable event types are also read. The client loads relation pages to count the latest vote per sender, ignores invalid and late votes, and honors only valid end events from the author or a moderator. Incoming polls with multiple allowed selections can be voted on with a selection limit. Authors and moderators can confirm closure; the permission comes from the fetched root event, including when it is older than the local timeline. Incomplete relation or decryption results block voting and closure, with a visible refresh path.

Static sharing sends a standard `m.room.message` with `msgtype: m.location`, `geo_uri`, an `m.location` object, and a text fallback. The manual coordinates remain available without device location access. Device geolocation is requested only on a separate button press and the dialog can close while permission is pending. Incoming `geo:` coordinates are bounded and rendered as a provider-free point with a system `geo:` link; no remote map or tracking resource is loaded. Both features use the same encrypted send guard as ordinary messages and the same room/thread surfaces.

If a user edits either coordinate while a device lookup is pending, the manual choice wins even if the browser delivers its earlier result later. Sharing still requires the separate confirmation button after the preview updates.

Unit and component tests cover payloads, relation aggregation, malformed events, permissions, encrypted-send refusal, dialogs, and card interactions. The aggregation tests also check competing valid closures in reversed relation order, including same-timestamp votes. Desktop and mobile Chromium tests cover layout and Chromium geolocation under Playwright-granted and Playwright-denied permissions: granted coordinates fill the preview but still require a separate share click, while denial retains manual entry. The [disposable live harness](live-matrix-tests.md) checks a poll create/vote/end round trip and static location rendering between two Aimtrix accounts in an encrypted Synapse room. Its pinned Element Web peer checks decrypted poll-question and location-map receipt, then votes through Element's native poll UI, replaces that vote from Aimtrix on the same account, and checks Element's closed state. The harness also sends an encrypted location from Element's location picker and requires Aimtrix to render the exact server-accepted event and a valid `geo:` link. The harness forces one encrypted relation per server page, replaces the vote again, and requires Aimtrix to show the changed tally after multiple successful pages. It also checks a separate unencrypted poll round trip, replaces Element's vote with an invalid answer through the standard relation API, checks the count drops to zero, and checks a server-accepted vote after closure does not reopen the count. A second plain poll receives two concurrent valid end events; both are accepted, and Aimtrix and Element show it closed. A manual pin sent through Element is retrieved by exact event context and rendered in encrypted Aimtrix; this does not establish passive live-sync arrival.
