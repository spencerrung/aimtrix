# First-use encryption confidence

Aimtrix discovers standard Matrix login flows for the selected homeserver before showing password or SSO sign-in. If discovery fails, it explains that availability is unknown. An empty account opens Home with encrypted direct-chat and encrypted-room starting points and a live account-health check. Recovery settings distinguish new setup from restoring existing secret storage and backup; setup refuses to overwrite either. An existing recovery key is checked against the account's secret-storage key before any cross-signing or backup operation. Recovery reset is a separate, confirmed destructive action using the SDK reset operation. A generated recovery key stays in memory until the user acknowledges saving it; clipboard and download failures keep it visible.

Incoming to-device verification requests are presented with the other user and device identity. The SDK owns request phases and crypto state. Aimtrix offers emoji SAS, QR display, and camera QR scan only when the corresponding Matrix capability and browser camera are available. The QR reader and generator load only when used. Cancellation and account shutdown detach listeners and stop the camera. The installed Rust SDK processes verified-device secret sharing internally; it does not expose an application approval callback. Aimtrix does not present a pretend secret-approval control. Users can verify a device or restore their existing recovery key instead. Decryption failures use SDK reason codes to distinguish pending, withheld, unverified-device, and historical-backup cases without exposing event contents or keys.

The browser and mocked tests cover sign-in capability gating, recovery safety, request cancellation, SAS, QR capability gating, and decryption guidance. Live two-device password/SSO setup and restore, QR/SAS interoperability with another client, and actual secret-gossip/withheld-key behavior still require disposable Matrix infrastructure and remain open acceptance boundaries for #160 and #161. SSO-only homeservers that require unsupported interactive authentication for cross-signing receive explicit guidance to use a trusted client for setup. Recovery reset deletes previous backup versions and can make old encrypted history unreadable.
